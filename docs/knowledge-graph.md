# 从错题本到知识框架

> 关于「AI 归纳题型」与「书本 → 知识框架」两个方向的设计思路。
> 目前不实现，先把想清楚的部分记下来，避免后面走弯路。

---

## 一、先厘清一组容易混淆的概念

现在系统里已经有「知识点」标签，再往上加东西之前，必须先分清三样东西：

| | 回答的问题 | 例子 | 现状 |
|---|---|---|---|
| **考点** | 这题**用到**什么知识 | 洛必达法则、夹逼准则 | 已有，`p.topics` |
| **题型** | 看到这种题**该怎么下手** | 含参分段函数求连续性、构造辅助函数证不等式 | 没有 |
| **知识点节点** | 这个概念**是什么、依赖什么** | 「洛必达法则」的定义、适用条件、前置概念 | 没有 |

**这三者混为一谈的话，三个都会变得没用。**

考点是「事后归类」，题型是「事前识别」。考试时真正起作用的是后者——你看到题的前十秒要判断出这是哪一类、第一步该做什么。错题本的价值上限，取决于能不能把「我错过的题」压缩成「我该识别的模式」。

## 二、题型归纳

### 为什么不能直接把 200 道题丢给 AI

上下文放不下，而且一次性生成的分类不稳定——同样的输入跑两次会得到不同的题型划分。必须做成 **map-reduce + 增量**。

### 三段式流程

```
① 指纹      每道题 → 一段结构化的解法描述（可并行，可断点续跑）
② 聚类      指纹集合 → 题型候选（这一步才需要看全局）
③ 回填      每道题 → 挂到某个题型上（可并行）
```

**① 解法指纹**（单题，走 analyze 槽）

不要让模型直接输出「题型名」——那样每道题都会造一个新名字。让它输出**可比较的特征**：

```json
{
  "signal":   "题面上能一眼看出的识别特征，如「分段函数在分界点处含参数」",
  "firstMove":"标准解法的第一步动作，如「令左右极限相等」",
  "keyTrick": "有没有关键技巧或构造，没有就填 null",
  "shape":    "结论的形态，如「解出参数值」「证明不等式」"
}
```

这四个字段是刻意设计的：`signal` 对应「怎么认出来」，`firstMove` 对应「怎么下手」，
合起来正好是题型的定义。

**② 聚类**

两条路，建议先走 A：

- **A. 嵌入 + 层次聚类**。把指纹拼成一句话送进 embedding 模型（Ollama 有 `bge-m3`、
  `nomic-embed-text`，走 `/v1/embeddings`，现有适配层基本能直接用），
  再做凝聚层次聚类，最后让 LLM 给每个簇命名。
  优点：N 大了也稳定，重跑结果一致，成本几乎为零。
- **B. 纯 LLM 分批归并**。每批 30 条指纹让模型合并，再把结果两两归并。
  优点：不引入新依赖。缺点：结果不稳定，N 大了会退化。

**③ 回填与增量**

题型库建好后，**新题优先挂到已有题型上**，找不到才新建——
和现在 `topics` 的复用机制完全同构。这个原则要贯穿始终，否则库会无限膨胀。

### 产出什么

- 每个题型一张卡片：识别信号 / 标准套路 / 关联考点 / 我的错题（附掌握度）
- **薄弱题型排行**：交叉 `mastery` 和 `reasons`，得到「你在『构造辅助函数』这类上 8 题错 6 题」
- 按题型出练习卷（打印模块已经支持按筛选导出，接上题型筛选即可）

## 三、书本 → 知识框架

### 目标形态

不是一棵树，是一张**有向图**：

```
节点：知识点 { 定义, 关键公式, 所属章节, 常见陷阱 }
边：  前置依赖 →   应用于 →   易混淆 ↔
```

树只能表达「章节包含关系」，但真实的知识依赖是跨章的——
「洛必达法则」的前置是「极限定义」和「导数定义」，这两个分属不同章。
用树表达不了，只有图能。

### 有了图能做什么

1. **根因回溯**。一道题错了，沿前置边往上找，
   看是不是根子在更底层的概念上没打牢。这是错题本最该有、但几乎没人做的功能。
2. **复习排序**。按拓扑序推荐——先补前置，再补依赖它的。
   比按遗忘曲线排序更符合理科的学习逻辑。
3. **覆盖度盘点**。图上标出「有题的节点」和「没题的节点」，
   一眼看出哪些概念自己从没练过。

### 构建方式

**按章节增量构建，绝不一次生成全书。**

理由有两条：上下文放不下；更要命的是，一次生成时早期的错误会污染后面全部内容，
而且没法定位是哪一步出的问题。按章走的话，错了只影响一章，重跑代价小。

```
一章的教材文本 → 抽取该章的知识点节点（定义/公式/陷阱）
              → 在【已有节点全集】里找前置依赖，只允许连已存在的节点
              → 人工在预览界面里校验、增删边
              → 合入图
```

「只允许连已存在的节点」这条约束很关键，否则模型会凭空捏造前置概念。

### 与现有 topics 的关系

现在 `p.topics` 是字符串数组。要变成图节点，需要给知识点独立身份：

```js
// 新增 store: concepts
{ id, bookId, name, aliases: [], def, formulas: [], chapterId, createdBy: 'ai'|'user' }
// 新增 store: edges
{ id, bookId, from, to, kind: 'requires'|'appliedIn'|'confusedWith' }
```

`p.topics` **保持字符串不变**，靠 `name` 或 `aliases` 解析到节点。
这样迁移是渐进的：图没建好之前，标签照常工作。

`aliases` 顺带解决了同义词问题——现在靠提示词约束模型复用词表，
终究不够硬；有了别名表就能真正合并「洛必达」和「洛必达法则」。

## 四、动手之前必须先有的东西

按依赖排序，前面的不做，后面的做了也是白做：

1. **题量到 100–200**。低于这个数聚类没有意义，会得到一堆只含一道题的「题型」。
2. **标签管理界面**。合并同义词、重命名、批量替换。
   现在标签只能一个个手动加删，等库长到几百个就治理不动了。
   这一步也是 `aliases` 的落地形态。
3. **可断点续跑的批量任务**。500 道题的全量分析必然会中途失败——
   网络断、限流、模型抽风。现在的 `ai/queue.js` 只有内存态，刷新即丢。
   需要把任务进度落库，支持「继续上次未完成的分析」。

第 3 条是硬前提。没有它，全量分析这个功能根本跑不完一次。

## 五、几条不要踩的坑

**不要让 AI 自动覆盖已有标签。** 全局操作必须走「预览 → 确认」。
单题分析可以直接落地（错了改一道题的成本很低），
但批量重写 500 道题的标签一旦跑歪，没有撤销就是灾难。

**不要把题型和考点合并成一个字段。** 见第一节。

**成本不是问题，别为了省 token 牺牲质量。** 500 题全量分析约 75 万 input tokens，
DeepSeek 上大概一块钱。该用长提示词、该带完整词表就带，
真正的成本是分析质量差导致的返工。

**本地模型只适合做提取，不适合做聚类和框架。**
7B 模型做 OCR 转录够用，但跨题归纳需要更强的推理能力，这部分应该走 analyze 槽。
现在的双槽设计正好支持这种分工，不用改架构。

## 六、一个可能更早见效的中间产物

在做完整题型聚类之前，有个成本低得多的版本值得先试：

**按已有考点标签做交叉统计**，找出高频共现的标签组合。
比如「洛必达法则 + 等价无穷小替换」共现了 12 次，
这本身就是一个事实上的题型，不需要任何 AI 调用，纯统计就能得到。

拿它先验证「题型这个维度对我有没有用」，再决定要不要投入做完整的聚类流程。
